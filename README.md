# Блок-схема для демонстрационного экзамена 2026

В модуле 2 демонстрационного экзамена нужно самостоятельно подготовить блок-схему алгоритма приложения по ГОСТ 19.701-90 и сохранить её в PDF.

Блок-схема показывает не внешний вид окон, а порядок действий и проверок внутри программы.

Например, на ней нужно показать:

- запуск приложения;
- открытие окна авторизации;
- выбор между входом и гостевым режимом;
- ввод логина и пароля;
- проверку пользователя в базе данных;
- обработку неправильных данных;
- определение роли;
- открытие нужного интерфейса;
- выход из приложения.

Готового решения в этом репозитории нет. Здесь объясняется, как самостоятельно построить правильную блок-схему.

## Что такое алгоритм

Алгоритм — это понятная последовательность действий, которая приводит к результату.

Например, алгоритм входа в приложение можно записать словами:

1. Открыть окно авторизации.
2. Получить логин и пароль.
3. Найти пользователя в базе данных.
4. Если пользователь найден — открыть приложение.
5. Если пользователь не найден — показать ошибку.

Программа выполняет действия и принимает решения в определённом порядке. Блок-схема изображает этот порядок графически.

## Что такое блок-схема

Блок-схема состоит из геометрических фигур и стрелок.

- фигура обозначает действие, условие, ввод данных, начало или конец;
- текст внутри фигуры объясняет, что происходит;
- стрелка показывает, какой шаг выполняется следующим.

Схему обычно читают сверху вниз и слева направо.

Простой алгоритм:

```text
Начало
   ↓
Получить число
   ↓
Число больше нуля?
 ├── Да  → Показать «Положительное»
 └── Нет → Показать «Неположительное»
                    ↓
                  Конец
```

## Чем блок-схема отличается от интерфейса и ER-диаграммы

Это три разных результата.

| Результат | Что он показывает |
| --- | --- |
| Макет интерфейса | Как выглядят окна, кнопки и поля |
| ER-диаграмма | Таблицы базы данных и связи между ними |
| Блок-схема | В каком порядке программа выполняет действия и условия |

В блок-схеме не нужно рисовать форму Windows Forms, расположение кнопок, цвета и размеры элементов.

Неправильно:

```text
Слева находится TextBox, справа находится зелёная кнопка.
```

Правильно:

```text
Пользователь вводит логин и пароль.
```

## Основные блоки

### Начало и конец

Используется овальная или скруглённая фигура **«Пуск-останов»**.

```text
╭─────────────╮
│   Начало    │
╰─────────────╯
```

В одной схеме обычно есть одно начало. Концов может быть несколько, но схема понятнее, когда ветви приводятся к общему завершению.

### Действие

Для обычного действия используется прямоугольник **«Процесс»**.

```text
┌──────────────────────────┐
│ Открыть список товаров   │
└──────────────────────────┘
```

В прямоугольнике можно написать:

- открыть окно;
- выполнить запрос к базе;
- определить роль;
- показать сообщение;
- загрузить товары.

Лучше помещать в один блок одно основное действие.

### Ввод или вывод

Для получения или отображения данных используется параллелограмм **«Данные»**.

```text
  ╱──────────────────────╱
 ╱ Ввести логин и пароль╱
╱──────────────────────╱
```

Примеры:

- ввести логин и пароль;
- получить данные пользователя;
- показать сообщение об ошибке.

### Условие

Для проверки используется ромб **«Решение»**.

```text
        ◇
   Данные верны?
     ╱       ╲
   Да         Нет
```

Текст внутри ромба лучше писать в форме вопроса:

- выбран гостевой режим?
- поля заполнены?
- пользователь найден?
- роль — администратор?

Из ромба должно выходить минимум две стрелки. Возле стрелок подписывают результаты, например **«Да»** и **«Нет»**.

### Стрелка

Стрелка показывает направление выполнения алгоритма:

```text
┌──────────────┐
│ Действие 1   │
└──────────────┘
        ↓
┌──────────────┐
│ Действие 2   │
└──────────────┘
```

Без стрелок невозможно понять порядок выполнения.

## Как соединять блоки

Соблюдайте простые правила:

1. Основное направление схемы — сверху вниз.
2. Все блоки должны быть соединены.
3. У каждой стрелки должно быть понятное начало и окончание.
4. Возле выходов из условия должны быть подписи.
5. Стрелки желательно не пересекать.
6. После ошибки нужно показать, куда возвращается пользователь.
7. Нельзя оставлять ветвь без продолжения или завершения.

Например, неправильный пароль не должен сразу завершать схему, если приложение позволяет попробовать снова:

```text
Пользователь найден?
 ├── Да  → Открыть приложение
 └── Нет → Показать ошибку
                    │
                    └──→ Вернуться к вводу
```

## Как сначала продумать алгоритм

Не начинайте сразу двигать фигуры в редакторе. Сначала запишите логику обычным текстом.

### Шаг 1. Определите начало и конец

Ответьте:

- с какого окна начинается программа;
- когда алгоритм считается завершённым.

### Шаг 2. Выпишите действия

Например:

- открыть окно входа;
- получить данные;
- обратиться к базе данных;
- открыть список товаров;
- показать ошибку.

### Шаг 3. Найдите условия

Ищите слова:

- если;
- иначе;
- да или нет;
- найден или не найден;
- заполнено или не заполнено.

Каждая такая проверка обычно становится ромбом.

### Шаг 4. Продумайте обе ветви

Для каждого условия ответьте:

- что происходит при ответе «Да»;
- что происходит при ответе «Нет»;
- куда программа переходит после каждой ветви.

### Шаг 5. Проверьте все пути

Мысленно пройдите схему как минимум несколькими способами:

- гость открывает приложение;
- пользователь вводит правильные данные;
- пользователь вводит неправильные данные;
- пользователь выходит.

Если какой-то путь невозможно пройти по стрелкам, схема неполная.

## Создание схемы в draw.io

draw.io также называется diagrams.net. Он работает в браузере и позволяет сохранить исходник схемы и PDF.

### Шаг 1. Откройте редактор

1. Откройте браузер.
2. Перейдите на [app.diagrams.net](https://app.diagrams.net).
3. Если появится выбор места хранения, выберите **Device**.
4. Нажмите **Create New Diagram**.
5. Введите имя, например `demo-exam-algorithm`.
6. Выберите **Blank Diagram**.
7. Нажмите **Create**.

### Шаг 2. Включите фигуры блок-схемы

1. В левой части редактора найдите раздел **Flowchart**.
2. Если его нет, нажмите **More Shapes**.
3. Установите флажок **Flowchart**.
4. Нажмите **Apply**.

### Шаг 3. Добавьте начало

1. Перетащите на лист фигуру **Terminator**.
2. Дважды щёлкните по фигуре.
3. Напишите `Начало`.
4. Разместите её в верхней части листа.

### Шаг 4. Добавляйте действия

1. Перетащите фигуру **Process**.
2. Напишите внутри короткое действие.
3. Расположите её ниже предыдущего блока.
4. Повторите для остальных действий.

### Шаг 5. Добавляйте условия

1. Перетащите фигуру **Decision**.
2. Запишите внутри вопрос.
3. Проведите из ромба две стрелки.
4. Дважды щёлкните по первой стрелке и напишите `Да`.
5. Подпишите вторую стрелку словом `Нет`.

### Шаг 6. Соедините блоки

1. Наведите указатель на фигуру.
2. Потяните появившуюся стрелку к следующей фигуре.
3. Отпустите кнопку мыши, когда следующая фигура подсветится.

Стрелка должна быть прикреплена к фигурам. Тогда она не потеряется при перемещении блоков.

### Шаг 7. Выровняйте схему

1. Выделите несколько блоков с зажатой клавишей `Shift`.
2. Используйте меню **Arrange → Align**.
3. Для одинаковых расстояний используйте **Arrange → Distribute**.

Не используйте много цветов. Чёрный текст, светлый фон и тёмные стрелки читаются лучше всего.

### Шаг 8. Сохраните исходник

Нажмите **File → Save As** и сохраните файл с расширением `.drawio`.

Исходник нужен, чтобы позже исправить схему. PDF редактировать значительно сложнее.

## Как нарисовать простой пример

Перед схемой демоэкзамена попробуйте изобразить алгоритм проверки возраста:

1. Начало.
2. Пользователь вводит возраст.
3. Программа проверяет: возраст не меньше 18?
4. При ответе «Да» выводится «Доступ разрешён».
5. При ответе «Нет» выводится «Доступ запрещён».
6. Конец.

Используйте:

- «Пуск-останов» для начала и конца;
- «Данные» для ввода возраста и вывода сообщения;
- «Решение» для проверки возраста;
- стрелки с подписями «Да» и «Нет».

Этот пример нужен только для тренировки и не является решением демоэкзамена.

## Как спроектировать схему для демоэкзамена

В задании требуется показать алгоритм запуска и авторизации приложения.

Перед рисованием ответьте на вопросы:

1. Какое окно открывается первым?
2. Что происходит при выборе гостевого режима?
3. Какие данные вводит пользователь?
4. Нужно ли проверять заполнение полей?
5. Как программа обращается к базе данных?
6. Что происходит, если пользователь не найден?
7. Что происходит после успешного входа?
8. Как программа определяет роль?
9. Какие интерфейсы открываются для разных ролей?
10. Что происходит при выходе из приложения?

Запишите ответы как последовательность действий и условий. После этого перенесите их в draw.io.

Не копируйте в схему весь программный код. Например, вместо SQL-запроса достаточно написать:

```text
Найти пользователя в базе данных
```

Вместо названия обработчика `loginButton_Click` напишите понятное действие:

```text
Проверить логин и пароль
```

## Экспорт в PDF

Когда схема готова:

1. Сохраните исходник через **File → Save**.
2. Откройте **File → Export as → PDF**.
3. Включите параметр **Crop**, если вокруг схемы слишком много пустого пространства.
4. Установите небольшую границу, например `10`.
5. Нажмите **Export**.
6. Сохраните файл под понятным именем:

```text
Фамилия_Блок-схема.pdf
```

Откройте полученный PDF и обязательно проверьте:

- схема полностью помещается на странице;
- текст читается;
- стрелки не обрезаны;
- подписи «Да» и «Нет» видны;
- нет пустых страниц.

## Частые ошибки

### Нарисован интерфейс вместо алгоритма

Не нужно изображать кнопки и поля формы. Показывайте действия программы и решения пользователя.

### Все фигуры прямоугольные

Условия должны быть ромбами, начало и конец — фигурами «Пуск-останов», ввод и вывод — блоками «Данные».

### В ромбе записано действие

Ромб содержит проверку или вопрос.

Неправильно:

```text
Выполнить авторизацию
```

Правильно:

```text
Пользователь найден?
```

### Нет подписей «Да» и «Нет»

Без подписей невозможно понять, какая стрелка соответствует каждому результату проверки.

### После ошибки нет возврата

Если пользователь может повторить ввод, стрелка после сообщения об ошибке должна возвращаться к соответствующему шагу.

### Стрелка ведёт в пустоту

Каждая ветвь должна прийти к другому действию, повторению или концу.

### В блоках слишком много текста

Используйте короткие формулировки. Подробности реализации остаются в коде и пояснении.

### Схема не помещается в PDF

Перед экспортом уменьшите схему, измените ориентацию страницы или включите обрезку по содержимому.

## Проверка перед сдачей

- есть блок «Начало»;
- есть блок «Конец»;
- показано открытие окна авторизации;
- показан гостевой режим;
- показан ввод логина и пароля;
- показана проверка пользователя по базе данных;
- неправильные данные обрабатываются;
- после успешного входа определяется роль;
- показано открытие соответствующего интерфейса;
- у каждого ромба есть минимум два выхода;
- выходы условий подписаны;
- все блоки соединены стрелками;
- текст легко читается;
- стрелки по возможности не пересекаются;
- исходник сохранён в формате `.drawio`;
- готовая схема сохранена в PDF.
